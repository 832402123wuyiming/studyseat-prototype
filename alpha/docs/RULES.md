# 预约规则基线 v1

规则来自附件计划和原型，是项目演示参数，不代表学校现行制度。阶段三已实现查询、创建、取消、签到、暂离、返回、结束、超时补处理以及管理规则和资源关闭。

| 参数 | 默认值 |
| --- | --- |
| 单次最长 | 240 分钟 |
| 提前天数 | 7 天 |
| 签到窗口 | 开始前 10 分钟至开始后 15 分钟，包含两端 |
| 暂离上限 | 30 分钟 |

服务端真实时间为准。数据库和接口统一 UTC `Z`，页面北京时间。提前天数按北京时间开始日期计算，允许今天至今天 +7 日（包含第七日），不是滚动 168 小时。单次时长允许恰好 240 分钟，开始允许等于服务端当前时刻，不能在过去。

房间每日开放边界包含开始和结束端点；结束在关闭时刻合法，超过一微秒即拒绝。00:00—24:00 房间允许跨午夜，其他房间的整个时段须连续处于每日开放时间内。房间与座位均须启用，已有未重开的关闭记录阻止对应资源预约；本阶段不开放关闭写入接口。

仅补处理后仍为 PENDING_CHECKIN 的预约可取消；不额外设置开始前截止时间，严格超过签到截止或已到预约结束的记录先过期。已取消重放返回首次结果，不重复更新 ended_at 或审计。正式规则确认仍由团队完成。

预约采用左闭右开区间 `[start,end)`，重叠为 `start1 < end2 && start2 < end1`，相邻不冲突。所有 API 写入时间必须先规范化再比较，不能把任意带偏移的原始字符串直接与 UTC 字符串比较。

| 状态 | 中文 | 允许的后续状态 |
| --- | --- | --- |
| PENDING_CHECKIN | 待签到 | IN_USE、CANCELLED、EXPIRED |
| IN_USE | 使用中 | ON_LEAVE、COMPLETED |
| ON_LEAVE | 暂离中 | IN_USE、COMPLETED、EXPIRED |
| COMPLETED | 已结束 | 无 |
| EXPIRED | 已超时 | 无 |
| CANCELLED | 已取消 | 无 |

签到截止时刻仍允许签到，严格超过截止才超时。重复签到、取消和结束不得覆盖首次有效时间或重复副作用；终态不能复活。已有预约保留创建时的规则版本与快照。页面签到仅表示页面操作，不能证明本人到场。

资源关闭遇到使用中或暂离中的预约时，拒绝直接关闭，要求先现场确认和结束后重新预览；这与旧 SRS TR-10 存在差异，**待团队确认**，本轮按原型实现，仍不视为已获团队批准的制度变更。重新开放不恢复已取消预约。旧 SRS 的 FR 编号以第 4.1 节为准：FR-02 账号密码、FR-08 结束超时、FR-09 取消、FR-12 规则。

阶段二创建与取消实测、独立连接并发和验收步骤见 [PHASE2.md](PHASE2.md)。阶段三已开放全部状态操作，并提供独立超时 CLI 与读取补处理，详见 [PHASE3.md](PHASE3.md)。

暂离截止恰好等于预约结束时按正常完成；只有暂离截止先到且严格超时才记为 EXPIRED。后台即使延迟处理也保留这个先后关系。资源关闭采用立即生效直至重新开放的方式，不支持未来定时关闭。
