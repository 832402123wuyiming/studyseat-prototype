# 首阶段规则基线 v1

规则来自附件计划和原型，是项目演示参数，不代表学校现行制度。本阶段只存储和读取规则；以下预约行为待后续实现与测试。

| 参数 | 默认值 |
| --- | --- |
| 单次最长 | 240 分钟 |
| 提前天数 | 7 天 |
| 签到窗口 | 开始前 10 分钟至开始后 15 分钟，包含两端 |
| 暂离上限 | 30 分钟 |

服务端真实时间为准。数据库和接口统一 UTC `Z`，页面北京时间。预约采用左闭右开区间 `[start,end)`，重叠为 `start1 < end2 && start2 < end1`，相邻不冲突。所有 API 写入时间必须先规范化再比较，不能把任意带偏移的原始字符串直接与 UTC 字符串比较。

| 状态 | 中文 | 允许的后续状态 |
| --- | --- | --- |
| PENDING_CHECKIN | 待签到 | IN_USE、CANCELLED、EXPIRED |
| IN_USE | 使用中 | ON_LEAVE、COMPLETED |
| ON_LEAVE | 暂离中 | IN_USE、COMPLETED、EXPIRED |
| COMPLETED | 已结束 | 无 |
| EXPIRED | 已超时 | 无 |
| CANCELLED | 已取消 | 无 |

签到截止时刻仍允许签到，严格超过截止才超时。重复签到、取消和结束不得覆盖首次有效时间或重复副作用；终态不能复活。已有预约保留创建时的规则版本与快照。页面签到仅表示页面操作，不能证明本人到场。

资源关闭遇到使用中或暂离中的预约时，拟拒绝直接关闭，要求先现场确认和结束后重新预览；这与旧 SRS TR-10 存在差异，**待团队确认**，本阶段未实现也不视为已批准变更。重新开放不恢复已取消预约。旧 SRS 的 FR 编号以第 4.1 节为准：FR-02 账号密码、FR-08 结束超时、FR-09 取消、FR-12 规则。
