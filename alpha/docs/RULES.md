# 预约规则基线 v1

规则来自附件计划和原型，是项目演示参数，不代表学校现行制度。阶段三已实现查询、创建、取消、签到、暂离、返回、结束、超时释放、规则版本和资源关闭；正式制度仍待团队确认。

| 参数 | 默认值 |
| --- | --- |
| 单次最长 | 240 分钟 |
| 提前天数 | 7 天 |
| 签到窗口 | 开始前 10 分钟至开始后 15 分钟，包含两端 |
| 暂离上限 | 30 分钟 |

服务端真实时间为准。数据库和接口统一 UTC `Z`，页面北京时间。提前天数按北京时间开始日期计算，允许今天至今天 +7 日（包含第七日），不是滚动 168 小时。单次时长允许恰好 240 分钟，开始允许等于服务端当前时刻，不能在过去。

房间每日开放边界包含开始和结束端点；结束在关闭时刻合法，超过一微秒即拒绝。00:00—24:00 房间允许跨午夜，其他房间的整个时段须连续处于每日开放时间内。房间与座位均须启用，已有未重开的关闭记录阻止对应资源预约；阶段三已开放关闭写入接口。

仅 PENDING_CHECKIN 可取消，沿用现有原型的按状态判断口径，不额外设置开始前截止时间。已取消重放返回首次结果，不重复更新 ended_at 或审计。

预约采用左闭右开区间 `[start,end)`，重叠为 `start1 < end2 && start2 < end1`，相邻不冲突。所有 API 写入时间必须先规范化再比较，不能把任意带偏移的原始字符串直接与 UTC 字符串比较。

| 状态 | 中文 | 允许的后续状态 |
| --- | --- | --- |
| PENDING_CHECKIN | 待签到 | IN_USE、CANCELLED、EXPIRED |
| IN_USE | 使用中 | ON_LEAVE、COMPLETED |
| ON_LEAVE | 暂离中 | IN_USE、COMPLETED、EXPIRED |
| COMPLETED | 已结束 | 无 |
| EXPIRED | 已超时 | 无 |
| CANCELLED | 已取消 | 无 |

签到截止时刻仍允许签到，严格超过截止才超时；返回同理，恰好到达暂离截止仍允许返回。重复签到、取消、暂离、返回和结束不得覆盖首次有效时间或重复副作用；终态不能复活。已有预约保留创建时的规则版本与快照，管理员修改规则只影响之后创建的预约。页面签到仅表示页面操作，不能证明本人到场。

超时释放由服务端在读取列表、查询余量、创建、取消和状态操作前统一执行，不依赖后台常驻任务：PENDING_CHECKIN 严格超过签到截止转为 EXPIRED；ON_LEAVE 严格超过暂离截止转为 EXPIRED；IN_USE 或 ON_LEAVE 到达结束时刻转为 COMPLETED。每条记录只执行一次迁移和一条审计，释放后座位可按区间重新预约。

资源关闭采用“先预览、后确认”：预览返回将被取消的待签到预约和阻止关闭的使用中/暂离中预约，不写业务数据；确认时重新校验并只在影响未变化时关闭。存在使用中或暂离中的预约时拒绝直接关闭，要求先现场确认和结束后重新预览；这与旧 SRS TR-10 存在差异，**待团队确认**，当前按该口径实现。关闭只取消待签到预约，重开不恢复已取消预约。旧 SRS 的 FR 编号以第 4.1 节为准：FR-02 账号密码、FR-08 结束超时、FR-09 取消、FR-12 规则。
